# Limitations and required calibration

This is an untested Mac/WhatsApp prototype, not a complete hands-free assistant. The repository tests only local parsing and safety cases; they cannot prove WhatsApp's AX tree on Hamdan's Mac or that its play/pause labels signal completion. Automatic playback is **off by default** until local calibration. WhatsApp media stays in the desktop app; the bridge presses its accessible play control instead of downloading audio. Network buffering, manual playback, Bluetooth routing, or a changed WhatsApp UI may stop the watcher. Text links/codes are not read aloud; look at WhatsApp for them.

- The exact-number check matches a locally chosen AX path; it must be proven to be the current selected chat header and fail on another open chat. A saved name alone does not prove the destination. GUI scripting still has a race between recheck and click. Keep WhatsApp foreground and supervise.
- Outgoing `send.scpt` requires exactly one text area in window 1, which may not hold on a different build. After a failed post-paste check, manually remove any unsent text. The clipboard may contain the transcript. Do not dictate secrets.
- The opt-in watcher requires a calibrated message-list path, incoming non-body direction marker, and unique voice play/pause button labels. If any are missing, do not enable it. It baselines existing notes and detects only newly appended visible groups. It stops on list shortening/reordering, ambiguous controls, failed AXPress, or an unverified transition. It does not read general notifications or poll other chats. Some completed controls may change path or label; then it stops safely.
- The current watcher has no durable WhatsApp message IDs, no recovered queue after a restart, no background arrival handling outside its post-send window, and no audio buffering or download. If the visible list virtualizes or a control does not return to its play state, sequential completion cannot be proven. Do not promise a guaranteed full-history or unattended audio experience.
- Test mic, hotkey, whisper-cli, AppleScript, permissions, selected Mac output and two sequential incoming notes on the actual machine. Stop on WhatsApp policy warnings or throttling; using the official desktop client does not remove account risk.

## Audio-attachment send path (second change)

The bridge's F8 release now sends its recorded M4A **as a document/audio-file attachment**, not a native WhatsApp voice-note bubble. It bypasses local Whisper transcription; the receiving side must be able to accept and understand the file. This has not been verified in Hamdan's WhatsApp client or in Instinct's inbound file handling. The local AppleScript controls require exact calibrated Attach, Document and preview Send labels. If the picker shape differs, it stops. A failed post-attachment header check can leave an unsent draft: clear it manually. The recording is deleted after the attempt, so a failed send is not retried automatically. Do not assume a successful AppleScript exit means server delivery; inspect the chat and receipt yourself. The active chat could still change between the final header check and the preview Send click.
