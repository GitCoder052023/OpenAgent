# Setup and first test

1. Install WhatsApp Desktop from the official source and link it to your phone. Open the Instinct WhatsApp chat and verify the phone number **+16508702892** from your actual conversation. Keep this chat open. The separate iMessage line is **not** this destination.
2. Install command-line tools, Python, SoX, and whisper.cpp per README. Check `which whisper-cli rec` and `whisper-cli --help`; Homebrew package commands and flags can change. Download a multilingual model from the official whisper.cpp model documentation: https://github.com/ggml-org/whisper.cpp/tree/master/models . The bundled download script uses their upstream model downloader; review it before running.
3. For Hinglish, `bash scripts/download-model.sh base` and set `BRIDGE_WHISPER_MODEL=models/ggml-base.bin` in `.env`. `base.en` is English-only. Larger models may be more accurate but slower. Set `BRIDGE_LANGUAGE=auto` so whisper chooses Hindi/English. Test code-switching for your accent.
4. macOS System Settings > Privacy & Security > Microphone: permit Terminal (or your terminal app), plus Accessibility: permit Terminal, the Python process if prompted, and your automation host. Grant Automation access to control WhatsApp/System Events when prompted. Restart Terminal if a new permission doesn't stick. The Mac may also require Input Monitoring for the F8 hotkey.
5. In WhatsApp Desktop, open the **unsaved number** chat. If it displays only a saved contact name, AX verification cannot prove the recipient; do not bypass it by searching for the name. `jarvis-bridge inspect > ax-tree.json` and find the selected chat header's `AXStaticText` or `AXButton` showing the exact phone number. Set `BRIDGE_HEADER_PATH` to its `path`, and verify the same path fails when a different chat is selected. Remove `ax-tree.json` after calibration; it can expose messages.
6. Run `jarvis-bridge speak --text 'Speaker check'` and select the desired Bluetooth speaker as the Mac's system output in Control Center. `say` uses system output. No SwitchAudioSource dependency is needed for MVP.
7. Run `jarvis-bridge run`, hold F8, say a short harmless test, release, and observe the actual WhatsApp chat. Esc stops. If sending fails, read [limitations](limitations.md). Never relax the number check just to make it work.

If using a keyboard where F8 is mapped to media playback, hold Fn+F8 or change the key in `bridge/main.py`. Python's keyboard listener may require Accessibility/Input Monitoring. Disable other global F8 shortcuts to prevent collisions.

## Opt-in reply reading and playback

1. Capture a harmless inbound test reply in this chat, then `jarvis-bridge inspect > ax-tree.json`. Do not share this dump; it contains chat content.
2. Find the selected chat's message-list container (`AXList`, `AXScrollArea`, or `AXGroup`) and set `BRIDGE_MESSAGE_LIST_PATH` to its `path`. Find a *non-body* accessibility title or description that marks **incoming** message groups and set `BRIDGE_INCOMING_MARKER` to its exact phrase. Test with one outgoing and one incoming bubble; if both have the same marker, leave the variables empty. The watcher must not read arbitrary notification text.
3. Run `jarvis-bridge run`. After a test send, it starts a 90-second watcher. It takes a baseline of current incoming messages and speaks only newly appended incoming groups. If the chat number/path changes, the list virtualizes, or layout reorders, it stops rather than guessing. `say` plays through macOS system output, including the selected Bluetooth speaker.
4. Never leave the opt-in watcher unattended: path/index stability, group marker semantics and direction must be checked on your Mac. If there is no stable incoming marker, automatic playback cannot be safely enabled with this approach.
